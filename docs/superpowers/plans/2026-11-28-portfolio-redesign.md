# Portfolio redesign implementation plan

Build against the [approved design](../specs/2026-11-28-portfolio-redesign.md) and retain the November release contracts. Each numbered stage is an independently reviewable PR. Complete the home first; the lesson mapping can then proceed independently of the editorial pages.

1. **Homepage.** In `site/src/pages/index.astro` retain fragment IDs and the HomeSignal component, set the two-line serif name, and render a featured project from published records. Add a no-JS-friendly route assertion in `site/tests/portfolio.spec.ts`. Inspect the rendered mobile and desktop composition and exercise reduced motion and replay.
2. **Shared shell and editorial pages.** Inspect SiteLayout, PortfolioNav, EditorialPage and EditorialList. Extract proven display and reading styles from home. Apply to projects, résumé, music and the general section index. Test empty and populated indexes, real project detail links, PDF delivery, consent-based playback and navigation at 320px.
3. **Library and search.** Update components under `site/src/components/notes` and pages under library, notes, resources and search. Use a pinned archive to verify a nested folder, collection group, note fragment, PDF and matching search result. Compare complete route/fragment inventories and asset hashes before accepting.
4. **Interview discovery.** Apply the pattern index to interview and practice/paths; use published catalog data for lesson links and counts. Cover all eight pilot routes, unpublished targets, search/filter empty states and study-path return navigation.
5. **Solver mapping and static lesson.** Inventory each pilot approach and current transcript anchors. Test mappings against verified source and trace digests in Notes before export. Extend the Portfolio importer and static lesson template compatibly. Exercise old snapshots, corrupted mappings, missing packages and a JavaScript-disabled reader before adding motion.
6. **Connected player.** In practice components implement the Two Sum layout first. Verify one lookup, insertion and return frame against the actual package, including reverse stepping. Extend the same cursor contract to the other seven pilots with their own data shapes. Check every package and transcript, keyboard operation, narrow screens, reduced motion, pause, replay and load failure.
7. **Private progress and secondary states.** Apply shared typography to the owner dashboard, authentication and error surfaces. Exercise anonymous denial, session expiry, save/reload, export, cross-device state and sign-out without exposing private data in static output.
8. **Certification and release.** Run the standalone gate with the pinned Node version and the combined release workflow on reviewed commits. Compare route and asset inventories, run throttled LCP, inspect phone navigation, playback, reader and player. Verify the hosted release marker, redirects, public lesson inventory and authenticated progress after approved publication. Retain the previous known-good artifact for rollback.

## Review evidence per stage
Capture the exact commit, failing baseline assertion for changed behavior, focused checks, final gate output and desktop/mobile screenshots. Record independently reviewed PRs and distinguish implemented, merged and live in the ledger. Keep the nine parked Notes files untouched. Scope exclusions and publication decisions stay with the existing release plan.
